# Beverage Recipe Blocker Resolution Review

**Status:** Review only. No ingredient, recipe, product, variant, POS, or inventory record is changed by this document. The five existing Warm Tales recipes remain version 1 and retain the label **SAMPLE / ASSUMED RECIPE QUANTITY — FOR SYSTEM DEMONSTRATION**.

This review covers all 27 blocked beverage products and all 39 blocked variants recorded in `Recipe_Build_Blockers.md`. A proposed sample assumption is not approval to write data. It must be accepted before the applicable ingredient or recipe is created.

## Classification key

1. **Existing ingredient can safely be used** — the ingredient identity and unit already match the proposed use.
2. **Existing ingredient requires unit clarification** — the row exists, but its unit does not yet have a sufficiently defined operational meaning.
3. **Existing ingredient identity is ambiguous** — a current ingredient may appear related but cannot safely be substituted or merged.
4. **Missing ingredient** — no current inventory identity represents the required stock.
5. **Recipe/business rule requires confirmation** — the menu name is insufficient to establish composition or make/buy treatment.

## Ice resolution

The current Ice record (`RM-004`) must remain unchanged for now. Its `pc` unit is technically supported, but “one piece” is undefined. The system can cost fractional or whole count quantities; it cannot convert an undefined piece into grams or milliliters, and no conversion should be invented.

Three data approaches are possible without changing the recipe architecture:

1. Define `1 pc` as one standardized ice cube, including an agreed physical size or average mass. This preserves `RM-004`, but it is only suitable if cube-based counting is credible for the demonstration and later physical counts.
2. Define `1 pc` as one sealed supplier bag. This preserves count inventory, but every recipe would consume a fractional bag and requires a confirmed bag size and usable yield.
3. Create a separately reviewed weight-based Ice ingredient using `g`, then use grams in recipes. This is operationally clearer for per-drink consumption but requires a new ingredient and a decision on the future status of `RM-004`; it must not be performed silently.

**Safest current decision:** keep `RM-004` unchanged and keep all ice-dependent recipes blocked until one definition is explicitly approved. No schema change is required for any option. The recommended operational choice is a weight-based record only if the café will actually measure or estimate ice by weight; otherwise, approve a precisely defined count/package basis.

## Recommended next approval sequence

First decide how Ice will be operationally measured. Next decide whether salted caramel may be represented for demonstration by existing Caramel Syrup plus Salt. Then approve specific stock forms for chocolate, matcha, tea, white mocha, green apple, strawberry, Oreo, java chips, bottled water, and any branded beverage composition. Only after those decisions should an Ingredient Master addition proposal be prepared. Recipe creation must remain a later, separately approved task.
